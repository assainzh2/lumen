# ADR-001: Lumen — distribution, signing and architecture

**Status:** Accepted
**Date:** 2026-10-07
**Deciders:** Assain

## Context

Goal: a personal iPhone app whose **home-screen / lock-screen widget** autonomously rotates interesting facts,
wisdom, micro-actions, reflection prompts, mental models, words of the day and gratitude prompts.

Hard constraints

- Runs 100 % on the phone. No server, no laptop at runtime, no network.
- €0 now. Must upgrade to the paid Apple Developer Program later **without code changes**.
- Positive effect, explicitly **not addictive**.

Forces

| Free Apple ID ("Personal Team") | Paid Developer Program (~€99/yr) |
|---|---|
| Provisioning expires after **7 days** | 1 year |
| Max 3 sideloaded apps, 10 App IDs / 7 days (app + widget = 2) | Unlimited |
| App Groups: works via SideStore; via Xcode it depends on the Xcode version | All capabilities (App Groups, iCloud, …) |
| No TestFlight | TestFlight |

When signing expires, the app **and its widget** stop working until re-installed.

## Decision

**Layered strategy: native app first, with redundancy against expiry.**

1. **Native SwiftUI app + WidgetKit extension** (iOS 17+), signed with the free Personal Team in Xcode.
2. **SideStore** on the phone auto-refreshes the 7-day signature over Wi-Fi, so no laptop is needed day to day.
3. **Scriptable backup widget** (free App Store app, never expires) that reads the *same* `content.json` and runs the
   *same* deterministic scheduler. If SideStore ever fails, the backup still works.
4. Paid upgrade later = select the paid team in Xcode and (optionally) tick App Groups. No code changes.

## Options considered

### A. Native SwiftUI + free signing (+ SideStore) — chosen as primary
| Dimension | Assessment |
|---|---|
| Complexity | Medium |
| Cost | €0 |
| Capability | Highest: exact timeline, interactive buttons, lock screen, StandBy, Smart Stack |
| Fragility | 7-day expiry, mitigated by SideStore + Scriptable fallback |

### B. Scriptable only — chosen as fallback
| Dimension | Assessment |
|---|---|
| Complexity | Low |
| Cost | €0, never expires, no Mac |
| Capability | iOS decides refresh times (imprecise); no in-widget buttons; limited layout |
| Fragility | Depends on a third-party app |

### C. Paid Developer Program — deferred
Same widget, but install once a year. The upgrade path stays open at zero migration cost.

### D. PWA / web app — rejected
iOS has no home-screen widgets for web apps. That alone rules it out.

## Architecture

```
┌──────────────────────── iPhone (no network) ─────────────────────────┐
│                                                                        │
│  Lumen.app (SwiftUI)                 LumenWidget.appex (WidgetKit)     │
│  ├ Today: today's revealed slots     ├ TimelineProvider: precomputes   │
│  ├ Saved: favorites                  │   48 h of entries at slot times │
│  └ About                             ├ Home: S / M / L                 │
│           │                          ├ Lock: rectangular / inline      │
│           │                          ├ Buttons: ♥ save, ↻ skip (cap 2) │
│           ▼                          └ Config intent: kinds + pace     │
│  ┌────────────── Core (pure Swift, shared by both targets) ────────┐   │
│  │ Item · ContentLibrary(content.json) · Scheduler · Store         │   │
│  └─────────────────────────────────────────────────────────────────┘   │
│                                                                        │
│  Scriptable/Lumen.js ── same content.json + same algorithm (backup)   │
└────────────────────────────────────────────────────────────────────────┘
```

### Deterministic, stateless scheduler (the core idea)
The widget never needs to "remember" what it showed. Everything comes from the clock:

- 6 fixed daily **slots**: 07:00, 10:00, 13:00, 16:00, 19:00, 21:30, each tied to a phase (morning / day / evening).
- `globalSlot = dayNumber × 6 + slotIndex` (dayNumber = local days since 2024-01-01).
- **Kind** for the slot = `plan[slot][day % 3]`. The plan fits the time of day: micro-actions and intentions in the
  morning, facts and models during the day, gratitude and review in the evening.
- **Item** = a seeded Fisher–Yates shuffle of that kind's pool (mulberry32 PRNG, FNV-1a seed of kind + phase + cycle),
  indexed by `globalSlot mod n`. No item repeats within a cycle, and every cycle is reshuffled.
- Swift and JS use the same 32-bit integer math, so the app, widget and Scriptable backup show the same item. Parity is
  checked by tests.
- **Resurfacing:** every 2nd day the 19:00 slot shows one of your saved favorites (spaced repetition).

Result: zero background work, zero battery cost. WidgetKit gets 48 h of entries at once and swaps them on time.

### Storage
`Store` uses `UserDefaults(suiteName: appGroup)` when the App Group entitlement is present and falls back to
`.standard` otherwise. On free signing without App Groups, the app's and the widget's favorites are stored
separately. With App Groups (paid, or SideStore) they are shared. The code is the same in both cases.

## Anti-addiction rules (enforced by architecture, not willpower)

1. **The widget is the product.** The app is a quiet shelf with no feed and no infinite scroll.
2. **No peeking ahead.** The Today screen reveals only slots whose time has passed.
3. **Skip is capped** at 2 per slot, so the widget can't become a slot machine.
4. **No streaks, badges, notifications or counters.** Nothing to "lose".
5. **Calm pace** option: 3 slots per day instead of 6.
6. **Finite library.** Content is a curated file, not generated endlessly.

## Consequences

- Easier: offline, private, instant, no battery drain, trivially testable (pure functions).
- Harder: new content requires editing `content.json` and rebuilding (Scriptable: just edit the file in iCloud).
- Revisit: (1) paid account for 1-year signing; (2) Apple Foundation Models (on-device LLM, iOS 26) to generate
  *reflection follow-ups* only, never facts, because a model can make facts up; (3) iCloud sync of favorites.
